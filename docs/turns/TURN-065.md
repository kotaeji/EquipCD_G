# TURN-065 실행 결과 보고서 내보내기 (HTML · CSV)

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.3.0`. 실행 규칙은 `seq-runtime/0.6.0` 그대로다. `release/` 는 다시 빌드하지 않았다. `README.md` 는 이 TURN에서 고치지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

6단계 「자세히」의 「실행 결과 요약」에 「보고서 내보내기 ▾」를 넣었다. 실행이 완료되거나 오류로 끝났을 때만 켜진다. 실행 전에는 「실행이 끝나면 보고서를 내보낼 수 있습니다」, 실행 중 · 일시정지 중에는 「실행 중에는 보고서를 내보낼 수 없습니다. 실행이 끝난 뒤 내보내세요.」가 단추 옆에 있다.

메뉴는 세 가지다. HTML 보고서, 단계 표 CSV, 로그 CSV. 파일을 만드는 함수는 `src/ui/runReport.ts` 에 있고, 화면은 그 결과를 내려받기만 한다. 내보내기는 모델을 쓰지 않는다. rev 와 Undo 는 그대로다.

HTML 은 파일 하나다. 글꼴 · 그림 · 스크립트를 밖에서 가져오지 않는다. 머리에는 프로젝트 이름, rev, 실행 시각(가상 시각, 요약 띠의 가상 시간과 같은 값), 앱 버전, 실행 규칙 버전이 있다. 한계 문구는 「논리 시뮬레이션 — 실제 장비 제어 / 안전 검증 아님」이다. 그 아래에 실행 요약(총 시간, 끝난 단계 수, 사이클, 시간당 생산량, 병목 — 화면과 같은 값), 가동 조건(투입 개수, 투입 간격, 오류 주입), 단계 표, 실행 결과 Gap, 가정 · 미정 값, Interlock 차단 이력이 온다. 오류로 끝나면 실행 화면 위 오류 칸과 같은 세 줄(무엇 · 왜 · 어떻게)이 제목보다 앞에 온다.

단계 표의 열과 순서는 화면 표와 같다. 로그 CSV 도 화면과 같이 최근 줄이 위다. CSV 는 UTF-8 BOM, 쉼표 구분이고, 쉼표나 따옴표가 있으면 따옴표로 감싼다. 같은 실행 기록은 내보낸 시각만 다르다. 그 시각과 파일 이름의 `YYYYMMDD-HHMM` 은 UTC 다. 파일 이름은 `<프로젝트 이름>_실행결과_<시각>.html`, 단계 표는 `_실행결과_단계_`, 로그는 `_실행결과_로그_` 다.

이름과 메모의 `<`, `>`, `&`, `"` 는 HTML 글자로 이스케이프한다.

## 화면 (1280×800)

Headless Chrome. 기기 픽셀 배율 1. 콘솔 오류 0. 앱 문서 스크롤 0 (`scrollWidth` 1280, `scrollHeight` 800).

5공정 예제를 끝까지 실행한 뒤 자세히를 열고 메뉴를 연 화면. 사이클 `00:11.100`, 시간당 `324.3`, 병목 `S3 가공 00:03.300`, 단계 `12 / 12`. rev 1, Undo 0.

- 메뉴, 라이트: `TURN-065-menu-light-1280.png`
- 메뉴, 다크: `TURN-065-menu-dark-1280.png`

같은 실행에서 받은 HTML 을 브라우저로 연 맨 위. 보고서는 인쇄용 문서이고, 어두운 쪽은 `prefers-color-scheme: dark` 다. 단계 표는 이 높이 아래에서 이어진다. 가로는 1280 안에 있다.

- 보고서, 라이트: `TURN-065-report-light-1280.png`
- 보고서, 다크: `TURN-065-report-dark-1280.png`

## 하지 않은 것

- `App.tsx`. 내려받기는 메뉴 컴포넌트 안에서 한다
- 실행 엔진, `README.md`, `release/` 재빌드, 의존성 추가

## 확인 필요

- 이 보고서를 그대로 자료에 쓸 수 있는가는 사람 검수(AC9)다. 이 문서는 완료로 적지 않는다.
- 내보낸 시각은 UTC 다. 같은 시각이면 어느 기기에서나 같은 파일이 되게 하려고 그렇게 했다.
- 실행 시각은 벽시계 시각이 아니라 가상 시각이다. 실행 기록에 벽시계 시각이 없다.
- 오류 세 줄은 실행 화면 위 오류 칸과 같다. 자세히 안의 오류 칸은 단계 이름 없이 「실행 …」으로 시작한다.
