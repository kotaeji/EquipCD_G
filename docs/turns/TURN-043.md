# TURN-043 실행 결과로 Gap · 병목을 알려 준다

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.3.0`. 실행 규칙은 `seq-runtime/0.4.0` 그대로다. `release/` 는 다시 빌드하지 않았다. `README.md` 는 고치지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

실행이 완료되거나 오류로 끝난 뒤, 그 실행 기록을 5단계 Gap 목록의 「실행 결과」칸에 올린다. 종류는 기존 5종을 그대로 쓰고, 행에 「실행 결과」를 붙인다. 정적 Gap의 판정식과 문구는 바꾸지 않았다.

- **병목 Unit** — 개체들이 기다린 시간 합이 가장 큰 Unit. 기다림이 있을 때만. 근거에 합, 기다린 개체 수, 까닭(Unit 가득 / Device 사용 중), 가상 시각 · `WAIT`/`WAIT_END` · 기다린 단계. 「이동」은 그 Unit 카드.
- **사이클 > 투입 간격** — 개체 3개 이상의 정상 상태 사이클이 투입 간격보다 길 때만. 근거에 두 값과 배출 시각. 「이동」은 자재 화면의 투입 간격.
- **한 단계가 통과 시간의 큰 몫** — 한 개 통과 시간에서 한 단계가 30% 이상일 때. 기준은 `src/model/runGaps.ts` 의 `RUN_STEP_SHARE` 한 곳이고, 행에 `[설계 제안]` 으로 적는다. 근거에 단계 시간과 통과 시간. 「이동」은 그 Action의 동작 시간.
- **실행 오류** — 타임아웃은 타이밍 병목, 조건 불충족 · 읽기 실패는 부족 I/O, 수용 부족은 부족 Unit, 교착은 타이밍 병목. 타임아웃의 「이동」은 그 Action의 타임아웃 칸. 이동은 TURN-038 과 같이 칸을 열고 테두리로 강조한다.

실행한 모델 rev 와 지금 rev 가 다르면 「이전 rev 의 실행 결과」를 붙이고 지우지 않는다. 초기화하면 안내로 돌아가고, 다시 실행하면 새 결과로 바뀌며 그 표시는 사라진다. 아직 실행하지 않았으면 「실행하면 여기에 실행 결과 Gap 이 나옵니다」.

6단계 요약 띠의 Gap 건수와 5단계 배지의 남은 항목, 「Gap (F6)」 건수가 실행 결과 Gap 도 센다. 실행 결과 Gap 은 프로젝트 파일에 저장하지 않는다.

5공정 예제 · 투입 5 · 간격 0 s 를 끝까지 실행하면 병목은 S2 식별이고 기다린 시간 합은 13.100 s 다. 정상 상태 사이클 4.500 s 가 투입 간격 0 s 보다 길다. 간격 20 s 에서는 사이클 항목이 나오지 않는다.

## 확인 필요

- 실행 결과 Gap 이 「어디를 고치면 빨라지는지」를 알려 주는가는 사람 검수(AC11)다. 이 문서는 완료로 적지 않는다.
- 한 단계 몫의 기준 30% 는 [설계 제안] 이다.
- 오류 코드를 기존 5종에 넣는 대응도 [설계 제안] 이다. 타임아웃 → 타이밍 병목, 조건 불충족 · 읽기 실패 → 부족 I/O, 수용 부족 → 부족 Unit, 교착 → 타이밍 병목.
- 병목 근거의 단계 이름은 그 Unit 을 기다린 단계다. 「이동」은 그 Unit 으로 간다.
