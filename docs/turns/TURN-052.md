# TURN-052 조건 한 줄 식 · 조건 검사(끊긴 참조 · 항상 거짓)

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.3.0`. 실행 규칙은 `seq-runtime/0.6.0` 그대로다. `release/` 는 다시 빌드하지 않았다. `README.md` 는 고치지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

조건을 화면마다 같은 한 줄로 읽고, 끊기거나 스스로 모순인 조건을 5단계 진단에서 본다. 실행 전 검사와 실행 엔진은 그대로다. 새 차단은 없다.

한 줄 식은 `src/model/conditionFormula.ts` 에 있다. 같은 조건은 같은 글을 낸다.

| 종류 | 글 |
|---|---|
| 신호 | `CYL-01.fwdDone = ON` (장치.포트, ON / OFF) |
| 자재 위치 | `자재 위치 = S2 식별` |
| 자재 상태 | `자재 상태 = 식별됨` |
| 자재 잡음 | `자재 잡음 = PCK-04` 또는 `자재 잡음 = 없음` |
| 미정 | `미정(메모)` |
| 묶음 | `CYL-01.fwdDone = ON 그리고 자재 위치 = S2 식별` |

검사는 `src/model/conditionCheck.ts` 의 순수 함수다. 같은 모델은 같은 결과를 같은 순서로 낸다. Action 사전·완료, 단계 진입, 분기·재시도·신호 기다림, Interlock 허용 조건을 본다.

| 종류 | 수준 | 까닭 |
|---|---|---|
| 끊긴 참조 | 오류 | 없는 신호 · Unit · Device, 자재 정의에 없는 상태 |
| 항상 거짓 | 오류 | 한 묶음 안의 같은 신호 ON+OFF, 자재 위치 둘, 자재 상태 둘, 잡은 Device 둘 |
| 겹침 | 안내 | 한 묶음 안에 같은 조건이 두 번 |
| 미정 | 미정 | 미정은 참으로 치지 않아 그 자리는 통과하지 못함 |
| 서로 반대인 갈래 | 안내 | 같은 병렬의 다른 갈래가 사전조건에서 같은 신호를 ON 과 OFF 로 요구. 「동시에 만족되지 않을 수 있음」 |

사전조건 OFF 와 완료조건 ON 은 정상이다. 같은 갈래 안이거나 병렬이 아니면 반대 갈래 안내를 내지 않는다. 기다림 블록의 기존 안내(TURN-049)는 그대로다.

5단계 「진단·저장」의 「조건」 묶음은 줄마다 어디 · 식 · 까닭 · 「이동」을 보여 준다. 「이동」은 그 조건 칸을 열고 강조한다. 3단계 Action 조건, 4단계 흐름 표의 분기 · 재시도 · 기다림, Interlock 허용 조건 옆에 같은 판정이 상태 기호로 보인다. 오류는 `!`, 미정은 `?`, 안내는 `△` 와 낱말 「안내」다. 안내만의 기호는 여섯 상태 밖에 없어서 가정 모양을 빌린다.

단계 바 5단계 남은 항목 수에 조건 오류와 미정이 들어간다. 안내는 진단 표에만 있다. 이 건수는 실행 전 검사를 실패로 바꾸지 않는다. 6단계 「실행 전 검사」 배지는 지금까지와 같이 `checkRunReadiness` 결과만 본다.

## 표기가 바뀐 곳

실행 로그와 실행 전 검사 문장은 그대로다. 로그의 신호 비교는 계속 `== true` 다.

| 자리 | 전 | 후 |
|---|---|---|
| 신호 한 줄 | `STP-03.상승 완료 = true` | `STP-03.upDone = ON` |
| Interlock 허용 조건 | `STP-03 · STP-03.상승 완료 = 참` 를 `, ` 로 잇던 글 | `STP-03.upDone = ON` 를 ` 그리고 ` 로 잇는 글 |
| 미정 | `미정: 메모` | `미정(메모)` |
| 자재 위치 · 상태 · 잡음 | `자재 위치 = S2 식별` 등 | 있는 대상은 그대로. 없으면 `없는 Unit` · `없는 Device` · `없는 신호` |
| 4단계 단계 줄의 조건 | `진입: … = true; …` | 사전조건과 진입 조건을 ` 그리고 ` 로 잇는다 |
| 6단계 단계 줄 | 기다림만 `… == true`. 일반 단계는 조건을 안 적음 | 같은 한 줄 식. 일반 단계는 사전·진입 조건 |
| 6단계 차단 안내 | 검사 문장만 | 조건으로 막힌 문장 뒤에 한 줄 식을 붙인다. 검사 결과와 로그는 그대로 |

예제 3종(5공정, 병렬, 흐름)은 조건 오류 0건, 안내 0건, 미정 0건이다. 실행 시각은 `00:11.100`, `00:02.500`, `00:13.100` 그대로다.

## 하지 않은 것

- 글로 쓰는 조건 언어, OR, 괄호, 비교, 타이머 조건
- 시퀀스를 따라가며 신호 값을 추적하는 분석. 기다림 블록의 기존 안내
- 실행 전 차단 추가, `src/runtime/`, 실행 규칙 버전
- 명령 찾기, 글자·간격 정리, 이름표
- `README.md`, `release/` 재빌드, 의존성

## 확인 필요

- 진단 문구만 보고 무엇이 잘못됐는가는 사람 검수(Matthew)다. 이 문서는 완료로 적지 않는다.
- 안내 기호는 가정 모양(△)에 낱말 「안내」를 붙인다.
- 조건 오류는 5단계 남은 항목에 들어가지만 실행을 막지 않는다. 미정 조건이 시퀀스 단계에 있으면 지금까지와 같이 실행 전 검사가 막는다.
