# TURN-055 Workspace 파일 묶음 내보내기 · 가져오기

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 프로젝트 파일 형식은 `0.3.0`. 묶음 형식은 `aurora-concept-designer/workspace-bundle` `0.1.0`. `README.md` 는 이 TURN에서 고치지 않았다. `release/` 는 다시 빌드하지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

「Workspace 파일 묶음」 화면에서 지금 Workspace 에 저장된 프로젝트를 파일 하나(`.aurora-workspace.json`)로 내려받고, 그 파일로 다시 넣는다. 「준비 중」 표시는 뺐다. 탐색기의 묶음 안내도 미구현이 아니다.

파일에는 형식 이름, 형식 버전 `0.1.0`, 만든 시각, 앱 버전, Workspace 이름, 저장된 프로젝트 전부가 들어간다. 프로젝트는 지금 프로젝트 파일 형식 그대로다. 저장 안 된 변경, 임시 저장, 보기 설정, 격리 보관함, 실행 기록은 넣지 않는다. 키 순서는 `stableStringify` 라서, 같은 Workspace 를 두 번 내보내면 만든 시각만 다르다. 저장 안 된 변경이 있는 열린 프로젝트가 있으면 내보내기 전에 「저장 안 된 변경은 빠집니다」를 묻는다. 화면에는 이름, rev, 저장 시각, 파일 크기가 보인다.

가져오기는 먼저 미리보기만 한다. 프로젝트마다 「새로 들어옴 / 같은 ID 있음 / 읽을 수 없음」이다. 미리보기만으로는 저장소가 바뀌지 않는다. 받는 곳은 「새 Workspace 로」(기본) 또는 「지금 Workspace 에 더하기」다. 이름이 겹치면 뒤에 번호가 붙는다. 같은 ID 는 사본(새 ID, 이름 뒤 「사본」, 기본), 건너뛰기, 덮어쓰기 중 고른다. 한꺼번에 같은 선택을 적용하는 단추도 있다. 덮어쓰기는 확인 창을 거치고, 처음 초점은 취소다. 덮어쓴 프로젝트가 열려 있으면 탭은 그대로 두고 「저장본이 바뀌었습니다 — 다시 열어 주세요」만 보여 준다.

읽을 수 없는 프로젝트는 들이지 않고 격리 보관함으로 돌려 까닭을 남긴다. 나머지는 계속 들인다. 묶음 파일 자체가 깨졌거나 형식이 아니면 세 줄(무엇 · 왜 · 어떻게)로 거부하고 저장소는 그대로다. 쓰기는 `applyAtomic` 한 번이다. 저장소가 가득 차 실패하면 가져오기 전으로 되돌린다. 끝나면 「들어옴 N · 사본 N · 건너뜀 N · 덮어씀 N · 격리 N」을 보여 주고, 새 Workspace 를 만들었으면 그쪽으로 바꿀지 묻는다. 저장소를 쓸 수 없는 메모리 전용 상태에서는 두 단추가 흐리고 까닭이 적힌다.

한 트랜잭션에 넣을 수 있는 키 상한을 16 에서 128 로 올렸다. 프로젝트 126 개와 저장 목록, Workspace 목록이 한 번에 들어간다. 그보다 많으면 쓰기 전에 거부한다.

## 하지 않은 것

- 여러 Workspace 를 한 파일로, 클라우드 동기화, 자동 백업, 버전 이력
- 프로젝트 파일 형식 변경, WPF 에서 열기
- 프로젝트 단위 JSON 내보내기 · 가져오기 동작 변경
- 도움말, 내 템플릿
- `README.md`, `docs/FEATURE-LIST.md`, 매뉴얼, `release/` 재빌드, 의존성

## 확인 필요

- 실제 브라우저에서 내려받은 파일을 다른 프로필에서 가져와 열 수 있는지는 사람 검수(Matthew)다. 이 문서는 완료로 적지 않는다.
- 덮어쓰기는 그 프로젝트가 있는 Workspace 에 본문만 바꾼다. 다른 Workspace 로 옮기지 않는다.
- 한 번에 126 개를 넘는 묶음은 거부한다. 복구 기록이 다룰 수 있는 키 수를 128 로 늘린 결과다.
- `docs/FEATURE-LIST.md` 와 매뉴얼의 FL-12 는 아직 📄 다. 이 TURN 은 그 문서를 고치지 않았다.
