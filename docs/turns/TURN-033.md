# TURN-033 3D 정보에 사이클 · 시간당 생산량 · 병목 · Gap, 가동 조건에 타임아웃

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.3.0`. 실행 규칙은 `seq-runtime/0.3.1`. `release/` 는 다시 빌드하지 않았다. `README.md` 는 고치지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

3D 보기의 왼쪽 「정보 표시」에 사이클 시간, 시간당 생산량(가정), 병목 Unit, Gap 요약을 더했다. 숫자는 `describeRunInfo` 가 만들고 화면은 그 결과를 그린다.

- 사이클 시간은 실행이 끝난 뒤의 총 가상 시간이다. 5공정 예제 `00:11.100`, 흐름 예제 `00:13.100`. 실행 전 · 실행 중 · 일시정지는 「실행 뒤 표시」다. 추정값은 만들지 않는다. 오류로 끝난 실행도 그 실행의 가상 시간을 보여 준다.
- 시간당 생산량(가정)은 `3600 ÷ 사이클 초`, 소수 첫째 자리다. 5공정 예제는 `324.3`. 안내 문구는 「자재를 한 개씩 이어서 넣는다고 본 값 — 실제 택트 아님」. 끝나기 전이나 오류로 끝나면 「—」.
- 병목 Unit 은 Unit 별 합계가 가장 큰 Unit 이다. 글자 「병목」으로 표시한다. 같은 값이면 앞 Unit. Unit 별 막대는 단계별 막대와 같은 모양이고, 정보 칸을 내리면 이어서 보인다.
- Gap 건수는 `analyzeGaps` 로 세고, 전체와 종류별이 5단계 Gap 배지와 같다. 「5단계에서 보기」는 5단계 Gap 화면으로 간다. 실행 중에도 보인다.

오른쪽 「가동 조건」에서 Action 마다 동작 시간 아래에 타임아웃을 고친다. `setQuantity`(field `timeout`), rev +1, 실행 취소, 「가정」 표시는 동작 시간과 같다. 같은 Action 의 타임아웃을 이어서 고치면 실행 취소 한 번에 묶인다.

- 타임아웃이 동작 시간보다 작거나 같으면 「타임아웃이 동작 시간보다 짧습니다 — 실행하면 TIMEOUT」. 저장은 막지 않는다.
- 실행 중 · 일시정지 중에는 타임아웃도 잠기고, 이유는 동작 시간과 같은 문장이다.
- 「이 화면에 들어온 뒤 바꾼 값 되돌리기」는 이 화면에서 바꾼 동작 시간과 타임아웃을 원래 값으로 돌린다. 그 사이의 다른 편집은 남긴다.

## 하지 않은 것

- 투입 간격, 여러 자재, 재공 수량, 런타임 규칙, 파일 형식
- 3D 장면 그리기(`Scene3D.tsx`, `describe.ts`, `shapes.ts`, `labels.ts`, `camera.ts`)
- 6단계 도면 탭, 4단계 흐름 표, Gap 계산 규칙, `README.md`, `release/`
- 의존성 추가

## 확인 필요

- 엔진은 완료 시각이 타임아웃과 같으면 그 단계를 성공으로 본다(기존 경계 규칙). 경고 문장은 이슈대로 타임아웃이 동작 시간보다 작거나 같을 때 보인다. 같으면 실행해도 `TIMEOUT` 이 아니다. 타임아웃이 더 짧을 때만 `TIMEOUT` 이다. 런타임 규칙은 바꾸지 않았다.
- 시간당 생산량은 자재 한 개를 쉬지 않고 이어서 넣는 가정이다. 실제 택트가 아니다.
- 왼쪽 정보 칸은 기존 200px 이다. 새 글자는 줄바꿈되고, 잘린 글자는 없었다. Unit 막대는 정보 칸을 스크롤하면 보인다.
- 숫자가 보고에 쓸 만큼 읽기 쉬운가는 사람 검수(Matthew)다.
