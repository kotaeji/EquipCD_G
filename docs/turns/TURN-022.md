# TURN-022 Station 시퀀스 흐름 — 분기 · 병렬 · 반복 · 재시도 · 그룹 실행 통합

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.3.0`. 실행 규칙은 `seq-runtime/0.3.0`. 그룹 규칙 `group-runtime/0.2.0` 은 코드에 남아 있다. `release/` 는 다시 빌드하지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

- `SequenceDraft.flow` 를 선택 필드로 두었다. 없으면 지금처럼 `steps` 순서대로 돈다. 5공정 예제는 `flow` 가 없고 총 `11.100 s` 가 그대로다.
- 흐름 종류: 단계, 분기(두 갈래), 병렬(2~4갈래, 끝에서만 합류), 반복(1~10), 재시도(추가 최대 `DEFAULT_MAX_RETRIES = 2`), Substation 단계(그 Unit의 시퀀스를 갈래로).
- 병렬 갈래 안의 병렬과 Substation 단계는 막는다. 그 밖의 중첩은 된다.
- 한 갈래의 오류는 전체를 멈춘다. 읽기 결과 신호를 조건으로 쓰는 분기 · 재시도가 있으면 결과 실패는 멈추지 않고 신호를 거짓으로 둔다. 「처음 N회만 실패」는 `simSettings.faults.readFailFirstN` 이다. 비우면 항상 실패다.
- 6단계의 「Station 시퀀스 / Substation 그룹」 선택과 그룹 단추 4개를 뺐다. 상태 줄 규칙은 `seq-runtime/0.3.0` 하나다. 4단계 Substation 시퀀스 편집은 그대로다. `src/runtime/group.ts` 는 실행 전 검사와 기존 테스트를 위해 남겨 두었다.
- 예제: 「흐름 예제」, 「병렬 예제」(Station 시퀀스가 Substation 단계 S1 → S2, 자재 1개). `+` 메뉴와 작업 시작 화면에 흐름 예제가 있다.

## 조정한 예제 값

- 흐름 예제의 S3 가공 실린더 전진은 사전조건에서 자재 상태 「식별됨」을 뺐다. 반복 2회째가 그 조건에 막히지 않게 하기 위해서다. 실린더 에셋에는 후진 Action이 없어 반복 본문은 전진 하나다.
- NG 갈래는 새 Action 「S2 NG 배출」이다. 자재 상태를 「식별실패」로 두고 `EXIT` 로 보낸다. 명령 · 완료 신호는 BCR-02에 새로 두었다.
- 병렬 예제에 자재 1개(초기 위치 S1)를 넣었다. 어느 Substation 시퀀스도 그 자재를 다루지 않는다.

## 하지 않은 것

- 갈래 사이 동기점, 조건 무한 반복, 세 갈래 이상 분기, 갈래별 일시정지
- Substation 시퀀스 안의 분기 · 병렬 · 반복
- 여러 자재 · 캐리어, 구조화 문장의 흐름 변환, Export · AML의 흐름 표현
- `docs/FEATURE-LIST.md`, 사용자 매뉴얼, `docs/traceability/`
- 의존성 추가, `release/` 재빌드, `assets/aml/*.aml`

## 확인 필요

- 병렬 안의 병렬과 Substation 단계는 막았다. 다른 중첩은 허용한다.
- 일시정지 · 재개를 끼우면 로그에 `PAUSE` · `RESUME` 줄이 더 있다. 그 줄을 빼면 단계 로그와 최종 상태가 같다. 5공정 예제의 기존 일시정지와 같다.
- 그룹 런타임 파일은 지우지 않았다. 화면에서는 그룹 실행을 시작하지 않는다.
- SFC는 1:1로 그린다. 글자는 11px이고, 차트보다 화면이 작으면 스크롤한다. 반복·재시도는 되돌림 화살표, 분기 합류는 직각 선이다.
