# TURN-018 실행 결과 요약 — 총 시간 · 단계별 시간

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 실행 규칙과 `engine.ts` 는 바꾸지 않았다. `README.md` 와 `src/ui/styles.css` 는 동시 진행 규칙으로 고치지 않았다. `release/` 는 다시 빌드해 커밋하지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

6단계 Station 실행의 접는 칸 「실행 도면, 로그, 차단 이동」안에 **실행 결과 요약**을 넣었다. 처음에는 펼쳐 있다. 실행 전 — 런타임이 없거나, 시작한 단계가 하나도 없을 때(`startMs` 가 모두 없음) — 「실행하면 단계별 시간이 여기에 나옵니다」만 보이고 표는 없다. 로그에 단계와 상관없는 줄만 있어도 같다. 초기화하면 다시 그 상태다.

실행이 시작되면 위 줄과 표가 나온다.

- 위 줄: `총 00:11.100 · 12 / 12 단계 · 가장 긴 단계 S3 가공 실린더 전진(가상 작업) 00:02.000`
- 표: 단계 이름, 상태(대기 / 진행 중 / 완료 / 오류), 시작, 끝, 걸린 시간. 시각은 `mm:ss.mmm`
- 가장 긴 단계 줄은 `var(--selected)` 바탕과 「가장 김」 글자
- 표 아래: 「가정 시간 기준 · 실제 택트가 아닙니다」

수치는 `summarizeRun` 이 엔진 `steps` 를 읽어 계산한다. 총 시간은 첫 단계 시작부터 마지막으로 끝난 단계의 끝까지다. 진행 중이거나 일시정지인 단계는 시작만 채우고 끝과 걸린 시간은 `-` 다. 타임아웃이면 그 단계는 「오류」와 오류 시각, 뒤 단계는 「대기」, 위 줄 앞에 「오류로 중단」이 붙는다.

요약은 상태 칸과 로그 표의 위, 실행 칸 너비에 둔다. 로그 열(약 336px) 안에만 두면 단계 이름이 줄바꿈되어 1280×800 에서 로그 표가 화면 밖으로 밀린다.

## 화면 (1280×800)

Chrome 157.0.8103.50, CSS 뷰포트 1280×800, devicePixelRatio 1. 콘솔 오류 0. 문서 가로 넘침 0, 실행 칸(`.ws-run > .center`) 가로 넘침 0.

요약을 실행 칸 맨 위에 두면 12행, 「가정 시간 기준」 줄, 로그 표의 머리와 첫 행(`RUN_COMPLETE` 또는 `TIMEOUT`)이 같이 들어온다. 오른쪽 「실행 로그」도 그대로다.

## 검증

구분해서 적는다. 통과 판정은 CI 를 따른다.

| 종류 | 결과 |
|---|---|
| 자동 테스트 | 로컬 `npm test` 28파일 436개 통과. 새 파일 `tests/run-summary.test.ts` 4개, `tests/ui-turn018.test.tsx` 4개. 그 가운데 하나는 로그에 `SENSOR_ON` 한 줄만 있고 모든 단계가 대기일 때 안내 문구만 보이는지 본다. 기존 `tests/engine.test.ts` 13개는 그대로 통과. 이 숫자는 이 문서 작성 시점의 로컬 실행이다 |
| 형식 검사 | 로컬 `npm run typecheck` 통과 |
| 빌드 | 로컬 `npm run build` 통과. 만들어진 HTML 은 커밋하지 않고 되돌렸다. `release/` diff 없음 |
| Chrome | 157.0.8103.50, CSS 뷰포트 1280×800, devicePixelRatio 1. 콘솔 오류 0. 완료 화면 위 줄은 `총 00:11.100 · 12 / 12 단계 · 가장 긴 단계 S3 가공 실린더 전진(가상 작업) 00:02.000`. 약 2초 뒤 일시정지하면 S2 스토퍼 하강이 「진행 중」이고 시작은 `00:01.600`, 끝과 걸린 시간은 `-` 다. 타임아웃 위 줄은 `오류로 중단 총 00:03.100 · 3 / 12 단계 · 가장 긴 단계 S2 바코드 읽기 00:02.000`. 뒤 단계는 「대기」와 `-`. 로그 표는 요약 아래에 남아 첫 행이 같이 보인다 |

## 확인 필요

- AC11 은 Matthew 검수 전이다. 이 문서는 완료로 적지 않는다. 실행이 끝난 뒤 어느 단계가 얼마나 걸렸는지 한눈에 보이는지는 사람 검수다.
- 5공정 예제의 시퀀스 단계는 12개다. Issue 예시의 `5 / 5` · `S4 이송 00:03.200` 은 문장 꼴이고, 화면 숫자는 예제 실행 값이다.
- 걸린 시간이 같으면 시퀀스에서 앞선 단계를 가장 긴 단계로 둔다. 예제에서는 S3 가공과 S5 컨베이어 배출이 둘 다 00:02.000 이라 S3 만 「가장 김」이다.
- 요약 칸은 로그 표만의 오른쪽 열이 아니라, 상태 칸과 로그 표 둘 다의 위에 두었다. 좁은 열에 두면 1280×800 에서 로그 표가 잘린다.
- 타임아웃 화면의 큰 제목이 「실행 차단과 수정」인 것은 기존 화면 규칙이다. 요약 표는 그 아래 접는 칸에 있다.
- 루카 검토: 단계 12개, 같은 시간이면 앞 단계를 「가장 김」, 요약을 상태 칸과 로그 표 위에 둔 것은 그대로 둔다.
- 실행 전 판정은 로그 길이가 아니라 시작한 단계가 없는지로 본다. 단계가 시작을 기록하기 전에 오류로 끝나면(전제 미충족) 시작 시각이 없어 안내 문구가 나온다.
