# TURN-028 Unit 안 Device 자동 정렬

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. `release/` 는 다시 빌드하지 않았다. `README.md` 는 이 TURN에서 고치지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 바뀐 조작

1. 2단계 「배치·연결」 도면 도식의 「크기 맞춤」 옆에 「자동 정렬」이 있다. Unit 하나가 선택됐거나, 고른 것이 모두 한 Unit의 Device일 때 켜진다. 그 밖에는 꺼져 있고, `title` 에 「Unit 하나를 고르거나, 한 Unit의 Device만 고르세요」가 있다.
2. 누르면 그 Unit 안의 Device만 다시 놓인다. 보내는 신호가 왼쪽, 받는 신호가 오른쪽이다. 다른 Unit에서 오는 쪽은 그 Unit이 있는 가장자리 열이다. 장치 상자(이름표·포트 포함)는 겹치지 않고, 사이 간격은 12px다. Unit은 내용에 맞게 줄거나 커지고, 왼쪽 위 자리는 그대로다.
3. 한 명령이다. rev +1, Undo 한 번에 Device 위치와 Unit 크기가 돌아온다. 다시 실행하면 정렬이 돌아온다. 이미 정렬된 상태에서 다시 누르면 「바뀐 것 없음」이고 rev는 그대로다. 실행 중·일시정지 중에는 단추가 꺼져 있다.

## 한 일

- 계산은 `src/model/deviceArrange.ts` 의 순수 함수다. 화면은 다시 계산하지 않는다. 명령은 `arrangeDevices` 다.
- 열은 Unit 안 신호(out → in)의 가장 긴 경로다. 순환이면 모델 배열 순서로 깊이 우선 탐색하고, 아직 스택에 있는 장치로 돌아오는 신호만 열 계산에서 뺀다. 연결 데이터는 지우지 않는다.
- 같은 열의 위아래는 이어진 장치의 줄 번호 평균이다. 같은 값이면 모델 순서를 유지한다. 한 열을 건너뛰는 신호는 그 사이에 빈 줄을 두어, 선이 중간 Device 몸통을 지나가지 않게 한다.
- 연결이 없는 Device는 남은 칸에 모델 순서대로, 칸이 없으면 왼쪽에서 오른쪽으로 이어서 놓는다. 신호가 하나도 없으면 한 줄에 대략 제곱근 개수만큼 나누어 같은 순서로 놓는다.
- 빈 Unit은 「크기 맞춤」과 같이 216×300이다. 다른 Unit의 위치·크기, 연결, 소속, id, 이름은 바꾸지 않는다.

## 확인 필요

- AC10은 Matthew 검수 전이다. 이 문서는 완료로 적지 않는다.
- 순환을 끊는 기준은 위 DFS다. 모델 순서상 뒤에서 앞으로 가는 신호를 항상 빼는 방식은 아니다. 순환에 속하지 않는 신호는 빼지 않는다.
- 왼쪽 Unit과 오른쪽 Unit에 둘 다 이어지면 내부 신호의 열이 이긴다. 한쪽에만 이어져도, 그 가장자리로 보내면 내부 신호의 좌→우가 깨질 때는 내부 신호를 지킨다.
- 이름표 너비는 11px 글꼴에서 ASCII 7px, 그 외 11px로 어림한다. 레이아웃 라이브러리는 넣지 않았다.
- 로컬 `npm run typecheck`, `npm test` (39파일 513개), 이 기록의 스크린샷을 확인했다. CI 판정은 이 기록이 아니다.
