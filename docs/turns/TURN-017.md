# TURN-017 자재가 있는 Unit 의 센서 신호

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.2.0` 그대로다. 실행 규칙은 `seq-runtime/0.2.0`, 그룹 규칙은 `group-runtime/0.2.0` 이다. `release/` 는 다시 빌드하지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

센서 신호(`role === 'sensor'`)의 값은 「자재가 지금 그 신호가 속한 Device 의 Unit 에 있는가」다. 템플릿 자식, 직접 놓은 센서, 사용자가 센서 역할로 만든 신호 모두 같다. 자재 위치가 그 `unitId` 와 같으면 `true`, 다른 Unit · `EXIT` · 자재 없음이면 `false`. 리밋 스위치도 이번엔 같은 규칙이다.

계산은 `src/runtime/engine.ts` 의 `applySensorSignals` 한 곳이다. Station 실행과 Substation 그룹 실행이 같이 쓴다. 다시 계산하는 때는 실행 초기 상태를 만들 때, Action 완료로 자재 위치가 커밋된 직후, 그리고 사전조건을 평가하기 직전이다. 값이 바뀌면 로그에 `SENSOR_ON` 또는 `SENSOR_OFF` 한 줄이 남고, 줄에는 Device 이름과 신호 이름이 있다. 초기화는 지금처럼 초기 상태로 돌아가므로 센서도 초기 자재 위치 기준이다.

`PRE_UNMET` · `POST_UNMET` · 타임아웃 문구는 신호 ID 대신 Device 이름과 신호 이름을 쓴다. 맞지 않은 조건이 센서면 「센서는 자재가 이 Unit 에 있을 때 켜집니다」를 붙인다. 단계 시작 로그의 명령·완료 신호도 같은 이름을 쓴다. 6단계의 켜진 신호 목록은 지금처럼 값이 `true` 인 신호를 이름으로 보여 주며, 센서도 그 목록에 나온다. 새 화면은 없다.

## 확인 필요

- AC11 은 Matthew 검수 전이다. 이 문서는 완료로 적지 않는다. 템플릿 유닛을 놓고 시퀀스에 넣어 끝까지 가는지는 사람 검수다.
- 사용자 매뉴얼은 이 TURN 범위 밖이라 고치지 않았다. 매뉴얼의 규칙 `0.1.0` 표기와, 센서 조건 Action 이 `PRE_UNMET` 으로 멈춘다는 문장은 이번 규칙과 다르다.
- 완료 후 조건(post)은 자재 위치를 커밋하기 전에 평가한다. 센서 값은 커밋 직후에 바뀐다. 도착한 Unit 의 센서가 켜져 있기를 post 가 요구하면, 그 단계는 커밋 전에 실패한다. 사전조건은 커밋 뒤의 값을 본다.
