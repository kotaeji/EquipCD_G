## 1. 한계 (사용자에게 그대로 안내)
- **Workspace = 이 브라우저(localStorage) 안의 관리 단위**다. 파일시스템 폴더가 아니며 다른 PC/브라우저와 자동 공유되지 않는다. 옮기려면 지금처럼 프로젝트별 JSON 내보내기/가져오기를 쓴다.
- Workspace 정보는 프로젝트 파일(JSON)에 들어가지 않는다 → 내보낸 JSON 형식은 그대로다.

## 2. 데이터와 저장
- 새 키 `ecd.v1.workspaces` = `{ formatVersion: 1, activeId, workspaces: [{ id, name, createdAt, updatedAt, projectIds[] }] }`. 프로젝트 본문(`ecd.v1.project.<id>`)·저장 목록(`ecd.v1.index`)은 그대로 쓴다.
- **비파괴 마이그레이션**: 레지스트리가 없으면 기존 저장 목록의 모든 프로젝트를 `기본 Workspace`(id `ws-default`)에 넣어 레지스트리만 새로 쓴다. 프로젝트 본문·저장 목록은 건드리지 않는다.
  - 반복 실행해도 같은 결과(멱등) — 바뀐 것이 없으면 쓰지 않는다.
  - 레지스트리가 깨졌으면 원문을 새 키 `ecd.v1.workspaces.corrupt.<시각>`에 쓰고 **읽기 확인까지 성공한 뒤에만** 기본 Workspace로 다시 만든다(경고 표시). 기존 백업 키는 덮어쓰지 않는다.
  - **백업이 실패하면 깨진 원문을 절대 덮어쓰지 않는다** → 이번 실행은 메모리 레지스트리로만 동작(경고). 같은 세션의 이후 레지스트리 쓰기도 백업 없이는 거부. 다음 시작에서 백업이 되면 그때 복구.
  - 레지스트리 **읽기 실패는 "없음"으로 취급하지 않는다** → 아무 것도 쓰지 않고 메모리로만 동작(경고). **이 세션에서는 Workspace 변경·프로젝트 저장·삭제가 모두 거부**된다(새로 고침 후 정상 읽기가 되면 원래 목록으로 다시 동작). 백업 확인 중 읽기 오류도 같은 처리이며 시작이 멈추지 않는다.
  - **쓰기 전 비교(rev 3)**: Workspace 목록을 바꾸거나 저장·삭제할 때, 저장소의 목록이 이 화면이 알고 있는 목록과 정확히 같을 때만 쓴다. 다르면(읽기 실패 세션, 다른 탭에서 변경 등) 아무 것도 바꾸지 않고 새로 고침을 안내한다.
  - 쓰기 실패 시 메모리 레지스트리로 계속 동작, 원본 키는 그대로(경고 표시).
  - 저장 목록(index)이 배열/항목 형식이 아니면 시작은 계속하되(경고) **목록 원문을 덮어쓰지 않고**, 저장·이름 변경·삭제는 거부한다.
  - 시작할 때마다 정합 복구: 어느 Workspace에도 없는 저장 프로젝트 → 기본 Workspace(없으면 첫 Workspace)로, 중복 소속 → 첫 소속만, 없는 프로젝트 id → 목록 표시에서 제외.
- 저장 목록의 50개 상한을 없앤다(51번째 저장 시 오래된 프로젝트가 목록·Workspace에서 사라지는 문제 방지, 데이터 삭제 없음). **한계**: 이전 버전의 상한 때문에 이미 목록에서 빠진 본문은 자동으로 찾아 넣지 않는다(본문은 남아 있음).
- **한꺼번에 쓰기(rev 2→3)**: 프로젝트 본문·저장 목록·Workspace 레지스트리를 바꾸는 모든 작업(저장, 새 ID 사본 저장, 닫힌 프로젝트 이름 변경, 삭제, 레지스트리 쓰기)은 하나의 묶음으로 쓴다.
  1. 먼저 끝나지 않은 이전 묶음을 복구한다. 복구할 수 없으면 아무 것도 바꾸지 않는다.
  2. **복구가 끝난 뒤에** 저장소를 새로 읽어 쓸 내용을 계산한다(복구 전에 읽은 목록으로 덮어쓰지 않음).
  3. 바꿀 키의 원래 값을 모두 읽고, 쓰기 전 비교 조건을 확인한다 — 하나라도 실패하면 아무 것도 바꾸지 않는다.
  4. 복구 기록 `ecd.v1.txn`(원래 값, 원래 값 해시, 새 값 해시, 전체 검사값)을 쓰고 읽기 확인 — 실패하면 아무 것도 바꾸지 않는다.
  5. 모든 키를 쓰고 다시 읽어 확인. 실패하면 원래 값으로 되돌리고(확인) 실패를 보고한다. 되돌리기가 실패했지만 모든 키가 확인 가능하게 새 값이면 완료로 보고한다.
  6. 그래도 남은 복구 기록은 다음 저장 직전 또는 다음 시작 때 처리한다: 모든 키가 새 값이면 완료로 보고 기록만 지우고, 아니면 원래 값으로 되돌린다.
- **복구 기록을 믿지 않는다(rev 3)**: 형식(정해진 필드만, 버전, 1–16개 항목), 대상 키 범위(프로젝트 본문·저장 목록·Workspace 목록만, 복구 기록 자신 금지), 중복 키, 값 종류, 해시 형식, 원래 값 해시, 전체 검사값을 모두 확인한다. 또 대상 키의 현재 값이 원래 값 또는 새 값 중 하나여야 한다.
  - 하나라도 맞지 않으면 **아무 키도 바꾸지 않고 복구 기록도 그대로 보존**하며, 이후 저장·Workspace 변경은 모두 거부한다(경고).
  - 검사값은 우발적 손상 확인용이며 암호학적 서명이 아니다.
  - **한계**: 손상된 복구 기록을 앱 안에서 치우는 기능은 없다. 이 상태에서는 저장이 계속 막히므로, 정리 방법(보관 후 해제 등)은 별도 결정이 필요하다. 그동안 작업은 JSON 내보내기로 보존한다.

## 3. 동작 규칙
| 기능 | 규칙 |
|---|---|
| Workspace 만들기 | 이름 필수(앞뒤 공백 제거, 연속 공백 1칸, 60자 이하), **같은 이름 금지(대소문자 무시)**. 고유 ID(`ws-…`)는 이후 바뀌지 않음. 만든 뒤 **자동 전환하지 않음** — 관리 창의 「전환」으로 이동(전환 규칙 적용) |
| Workspace 전환 | 실행/일시정지 중이면 막음. **저장 안 된 편집이 있는 탭이 하나라도 있으면 막음**(변경 유지, 먼저 저장/닫기 안내). 편집 없는 미저장 새 탭만 있으면 "닫힘" 확인(기본 취소). 전환하면 현재 탭을 닫고 새 Workspace의 가장 최근 프로젝트(없으면 빈 새 프로젝트)를 연다 |
| Workspace 이름 변경 | 만들기와 같은 검증. ID 불변 |
| Workspace 삭제 | **빈 Workspace만**(저장 프로젝트 0개), **마지막 Workspace 금지**, **현재 Workspace 금지**(먼저 전환). 프로젝트 연쇄 삭제 없음. 확인 창 기본 취소 |
| 프로젝트 추가 | 기존 「+ 빈/5공정/병렬 예제」「JSON 가져오기」로 탭을 만들고, **저장하는 순간 현재 Workspace에 소속**. 새 이름은 같은 Workspace 안에서 겹치지 않게 번호를 붙임 |
| 프로젝트 열기 | 「프로젝트…」 목록·최근 저장은 **현재 Workspace 것만** |
| 다른 Workspace 소속 ID 저장 | 덮어쓰지 않고 막음 → 「새 ID 사본으로 저장」 선택 가능. 사본 본문·목록·현재 Workspace 소속을 한꺼번에 쓰며, **실패하면 사본을 만들지 않고 현재 탭을 그대로 두고 오류만 표시**(성공 안내 없음) |
| 열린 프로젝트 이름 변경 | 탭의 ✎ → 모델 명령(`renameProject`): rev +1, **Undo/Redo 가능**, 저장 전까지 미저장 표시. 탭·헤더·내보내기 이름은 즉시, 저장 목록 이름은 저장 시 반영. 같은 Workspace 안 저장 프로젝트·열린 탭과 중복 금지 |
| 닫힌 저장 프로젝트 이름 변경 | 목록에서 → 저장본 이름을 바꿔 다시 저장(rev +1, 저장 후 읽기 확인, 본문·목록 한꺼번에 — 실패 시 둘 다 원래 이름). Undo 대상 아님. 열린 프로젝트는 여기서 막고 탭에서 바꾸도록 안내 |
| 프로젝트 삭제 | **닫힌 저장 프로젝트만**. 열린 프로젝트는 버튼 비활성+안내. 확인 창에 이름·ID·"영구 삭제·되돌릴 수 없음"·JSON 내보내기 버튼, **기본 포커스 취소**. 저장 목록·본문·Workspace 소속을 한꺼번에 삭제 — 중간 실패 시 원래대로 되돌리거나 다음 시작 때 복구하여 **프로젝트가 목록에서 사라진 채 남지 않음** |
| 탭 닫기 | **저장 데이터 삭제가 아님**(기존 그대로, 미저장 경고 유지) |
| 트리 접기/펼치기 | Station·Substation 행에 ▸/▾. 클릭(▸/▾)·키보드 → / ←. 「모두 펼치기」= Station+Substation 펼침, 「모두 접기」= **Station과 Substation 모두 접기**(Station 행만 보임, Station을 펼치면 Substation은 접힌 채. 이미 접힌 Station을 펼치지 않음). 처음엔 모두 펼침 |
| 대화상자 (rev 4) | 관리 창·이름 창·확인 창 모두: 열리면 포커스가 안으로 이동(확인 창은 기본 「취소」), **Esc는 맨 위 창만 닫음**(확인 창의 Esc·바깥 클릭 = 취소, 아무 동작도 실행하지 않음), 닫히면 연 버튼으로 포커스 복귀. **대화상자가 열린 동안 프로젝트 단축키(Ctrl+Z/Y/Shift+Z, Delete/Backspace, Esc 모드 해제)는 동작하지 않음** — 글 입력칸의 브라우저 기본 실행 취소는 그대로 |
| 트리 키보드 | → 펼치기 / ← 접기(Device에서는 부모 Substation으로 이동) / ↑↓ 보이는 항목 이동 / Enter·Space 선택(기존). `aria-expanded`는 실제 상태와 일치, 자식 없는 행은 없음. **rev 4: 하위 `role=group`은 부모 treeitem 안에 위치(소유 계층), `aria-level` 1/2/3** |
| 접기 상태 분리 | UserView `treeCollapsed[프로젝트 id]`에만 저장. 선택·그룹 실행 대상·history·rev·내보내기 불변. 접기 버튼은 선택하지 않음 |
| 숨겨진 선택 | 선택 항목이 접힌 행 안에 있으면 그 행에 「● 선택 포함」 표시. **자동 펼침은 하지 않음**(단계 이동·차단 이동 버튼도 접기 상태를 바꾸지 않음 — 사용자가 정한 보기 유지, 선택은 Canvas/속성 패널에서 계속 보임) |

## 4. 인수 조건
**AC의 역할**: 아래 AC는 이 TURN의 검수 기준이다. 새 요구가 아니며, 기존 C01(Workspace·다중 Project·저장/열기)과 N03(왼쪽 Workspace/Project 조작) 중 사용자가 이번에 확정한 범위를 브라우저 안 관리 단위로 구체화한 것이다. AutomationML 표준 기능이 아니다. 판정은 개발 자동 / 독립 재검수 / 실제 GUI를 따로 적는다(2026-11-08 KST 기준).

| AC | 내용 | 관련 요구 | 개발 자동 | 독립 재검수 | 실제 GUI |
|---|---|---|---|---|---|
| AC1 | 마이그레이션: **저장 목록(index)에 있는** 저장 프로젝트 전부를 기본 Workspace로 이관(과거 50개 상한으로 목록에서 빠진 본문은 범위 밖, M1), 본문·목록 바이트 불변, 반복 실행 멱등, 쓰기·읽기·백업 실패와 깨진 레지스트리에서 원본 보존 | C01, N03 | PASS | PASS(rev 3 저장소) | 해당 없음(관찰 불가) |
