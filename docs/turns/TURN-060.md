# TURN-060 자료 입력 1차 — IO 리스트 · 사양표 XLSX

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. `README.md` 는 고치지 않았다. `release/` 는 다시 빌드해 크기를 재고 커밋하지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

「자료 입력」에서 XLSX 하나를 이 브라우저 안에서만 읽는다. 업로드와 외부 전송은 없다. 시트 목록과 고른 시트의 앞 20줄이 나오고, 머리 줄 번호는 기본 1이다. 파일 5MB, 시트 5,000줄을 넘기면 읽지 않고 까닭을 세 줄(무엇 · 왜 · 어떻게)로 알린다. XLSX가 아니거나 깨진 파일도 같다. 수식은 저장된 값만, 병합 셀은 첫 칸만, 그림과 매크로는 무시한다.

열마다 Unit 이름 · Device 이름 · Device 종류 · 신호 이름 · 신호 방향 · 주소 · 메모 · 쓰지 않음을 고른다. 머리글로 추측해 미리 채우고 「추측」이라고 표시한다. 사람이 바꾸거나 「매핑 확정」을 누르면 추측이 빠진다. Device 이름 열이 없으면 「후보 만들기」로 못 간다.

Device 종류 글자는 에셋 이름과 별칭으로만 맞춘다. 실린더 · Cylinder 는 실린더다. 못 맞춘 값과 유닛 템플릿 이름은 「종류 미지정」이다. 종류를 지어내지 않는다.

「후보 만들기」는 같은 Unit 이름, 같은 Device 이름, 같은 Device의 같은 신호 이름을 하나씩 묶어 입력 후보표에 넣는다. 출처는 `import` 이고 파일 이름 · 시트 · 줄 번호가 남는다. 종류까지 맞추고 매핑을 확정한 Device는 신뢰도 보통이다. 종류 미지정이나 추측 매핑은 낮다. 모델이나 후보표에 같은 이름이 있으면 「이미 있음」이고 확인 전에는 반영하지 않는다. 후보만 만든 직후에는 Unit · Device 수와 rev가 그대로다.

반영은 지금 규칙이다. 확인한 것만, 낮은 신뢰도의 Device와 신호는 다시 확인해야 반영된다. 같은 묶음에서 확인한 Unit 후보 안에 그 Unit 이름의 Device를 넣는다. 신호는 그 Device에 더한다. 에셋에 같은 이름(포트 라벨)이 있으면 주소만 채우고 방향은 바꾸지 않는다. 한 번 반영은 Undo 한 번이다.

형식 표는 XLSX 「지원(IO 리스트 · 사양표)」, PDF · DWG · USD는 「추출 미구현」이다. 자료 입력의 「준비 중」 표시는 뺐다. 예시 파일은 `docs/samples/io-list-5step.xlsx` 다.

의존성은 `fflate` 0.8.3 (MIT) 하나다. XML은 이미 있는 `fast-xml-parser` 다. `xlsx` 패키지는 쓰지 않았다. `package-lock.json` 은 루트 의존성에 `fflate` 를 넣고, 잠겨 있던 0.8.3 의 `dev` 표시를 뺀 것이다.

로컬 `npm run build` 의 릴리스 HTML은 외부 참조 없이 한 파일이었다. 크기는 4,981,737바이트에서 5,008,177바이트로 26,440바이트 늘었다. 그 HTML은 커밋하지 않았다.

## 확인 필요

- AC14는 Matthew 검수 전이다. 실제 IO 리스트의 머리글이 이 추측으로 쓸 만한지는 사람 검수다.
- 날짜 칸은 엑셀 일련번호로 남는다. 표시 형식으로 바꾸지 않았다.
- 에셋에 같은 신호 이름이 있으면 주소만 채운다. 표의 입력/출력은 그 신호의 방향을 바꾸지 않는다. 명령 포트는 에셋에서 장치로 들어오는 `in` 인 경우가 있어, PLC의 DO와 글자가 다를 수 있다.
- 에셋에 없는 신호는 새로 만든다. 출력은 역할 `command`, 입력은 `sensor` 다. 메모 칸은 신호 필드가 없어 출처 글에만 남긴다.
- Unit 후보는 기존 반영 규칙이 낮은 신뢰도를 막지 않는다. 확인하면 만들어진다. Device와 신호는 낮은 신뢰도면 확인해도 반영되지 않는다. 추측을 지우려면 「매핑 확정」을 누른 뒤 후보를 만든다.
- 압축을 푼 크기가 32MB를 넘으면 읽지 않는다. 이 한도는 이슈의 5MB · 5,000줄 옆에 둔 안전 한도다.
