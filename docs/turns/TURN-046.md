# TURN-046 확인한 Interlock 이 실행을 막는다

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.3.0`. 실행 규칙은 `seq-runtime/0.5.0`. `release/` 는 다시 빌드하지 않았다. `README.md` 는 고치지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 실행 규칙 (seq-runtime/0.5.0)

1. Interlock 에 선택 값 「규칙」이 있다. 없는 파일은 지금과 같이 읽히고 실행된다. 규칙은 두 가지다.
   - 허용 조건 — 이 Action 은 조건이 모두 참일 때만 시작한다. 조건은 기존 `Condition`(신호 · 자재 위치 · 자재 상태 · 잡음)이다.
   - 동시 금지 — 이 Action 은 저 Action 이 진행 중인 동안 시작하지 않는다.
2. 확인됨이고 규칙이 있는 Interlock 만 실행에 적용한다. 미확인 · 거절 · 규칙 없음 · 규칙 미정은 적용하지 않는다.
3. 단계가 시작하려는 순간, 적용되는 Interlock 이 막으면 그 단계는 시작하지 않는다. 명령 신호도 켜지 않는다. 실행은 `INTERLOCK_BLOCK` 으로 멈춘다. 메시지에 Interlock ID · 설명 · 거짓인 조건(또는 진행 중인 상대 Action)이 있다. `PRE_UNMET` · 오류 주입과 코드가 다르다.
   - 병렬 갈래 · Substation 그룹 · 여러 개체에서 동시 금지에 걸리면 오류가 아니라 대기한다. 상대 Action 이 끝나면 시작한다. 기다림 기록(`WAIT` / `waitNote`)에 「Interlock」이 남는다.
   - 허용 조건이 거짓이면 기다려도 풀리지 않으므로 병렬 · 여러 개체에서도 `INTERLOCK_BLOCK` 이다.
   - 한 Action 에 허용 조건과 동시 금지가 같이 있으면 허용 조건을 먼저 본다.
4. 확인됨이지만 규칙이 없는 Interlock 은 실행을 막지 않는다. 실행 전 검사에 「확인됨 · 규칙 없음 — 실행에 적용되지 않음」 안내를 낸다. 차단이 아니다. 대상 Action 이나 조건 Signal 이 지워지면 규칙은 「미정」이 되고 깨진 id 는 남지 않는다. 확인됨 · 미정도 안내만 하고 실행은 막지 않는다.
5. 같은 모델은 언제나 같은 로그를 낸다. 5공정 예제의 규칙 2건은 설명과 맞고, 확인은 「미확인」이라 실행 결과 `00:11.100` 은 바뀌지 않는다.

## 한 일

- `Constraint.rule` 선택 값. 허용 조건 · 동시 금지 · 미정. 저장하면 다시 읽어도 같다. 형식 버전은 `0.3.0` 이다.
- 3단계 Interlock 줄에서 추가 · 삭제 · 설명 · 확인 · 막을 Action · 꼴 · 조건 또는 상대 Action 을 고친다. 한 줄 요약이 같이 보인다. 편집은 rev +1 이고 Undo 한 번으로 돌아온다. 실행 중 · 일시정지 중에는 잠긴다. 「자동 안전 승인은 없습니다」는 유지한다.
- 순차 · 흐름(분기 · 병렬 · 반복 · 재시도) · Substation 단계 · 여러 개체 · Substation 그룹이 같은 판정을 쓴다.
- 막히면 요약 띠 · 왼쪽 단계 줄 · 도면 / 3D 표식에 오류와 「Interlock」이 보인다. 「실행이 막힐 때」 안내와 「자세히」의 Interlock 차단 이력(가상 시각 · Interlock · 단계 · 까닭)에서 「이동」하면 그 Interlock 줄이 열리고 강조된다.
- 5단계 실행 결과 Gap 에 `INTERLOCK_BLOCK` 이 들어가고, 그 「이동」도 같은 Interlock 줄로 간다.
- Export 초안 파일의 확인된 Interlock 에 규칙이 들어간다.

## 하지 않은 것

- 안전 인증 · 실제 장비 Interlock · 자동 생성 · 자동 확인
- 조건 식 문법 · 모순 진단
- `src/storage/` 의 자동 저장, 작업 정보 줄, 시작 화면
- `Canvas.tsx` 의 선 · 미니맵 · 팔레트 접기. 도면 장치의 오류 표식에 「Interlock」 글자만 더했다
- `README.md`, `release/` 재빌드, 의존성 추가
- `GROUP_RULES_VERSION` 은 `group-runtime/0.2.0` 그대로다. 그룹 실행도 위 판정을 쓰지만, 이 TURN 이 올린 버전 상수는 `RUNTIME_RULES_VERSION` 이다

## 확인 필요

- Interlock 규칙을 정하는 화면이 이해되고, 막힌 까닭이 바로 읽히는가(AC15)는 사람 검수다. 이 문서는 완료로 적지 않는다.
- 허용 조건이 거짓인 재배치 모델에서 Interlock 을 확인하지 않으면, Action 자신의 전제 때문에 `PRE_UNMET` 으로 멈춘다. Interlock 코드는 아니다.
- 그룹 규칙 버전을 같이 올릴지는 이 문서에 적지 않고 두었다.
