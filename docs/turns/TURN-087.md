# TURN-087 차이 보기 · 키보드 상태 줄의 작은 마무리

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.3.0`. 실행 규칙은 `seq-runtime/0.10.0`. `README.md` 와 `release/` 는 이 TURN에서 고치지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

- 시퀀스와 블록의 순서 줄은 내부 ID 목록 대신 바뀐 내용을 말한다. `describeOrderChange` 가 `diffProjects` 안에서 같은 두 모델을 항상 같은 글로 낸다.
  - 더함: `더함: 신호 기다림(S2 뒤)`. 맨 앞에 넣으면 `(맨 앞)`.
  - 뺌: `뺌: S3 스토퍼 상승`.
  - 옮김: `옮김: S4 피커 잡기 3번째 → 5번째`. 자리는 그 목록의 1부터 센 자리다. 앞뒤가 늘거나 줄어서 자리만 밀린 것은 옮김으로 세지 않는다.
  - 글 순서는 뺌, 더함, 옮김이다. 변화가 6개를 넘으면 앞의 6개와 `그 밖 N개` 만 남긴다.
- Station 시퀀스의 단계 목록과 흐름, Substation 시퀀스, 블록 안 목록(반복·재시도 본문, 분기 갈래, 병렬 갈래)이 같은 함수를 쓴다. 다른 프로젝트, JSON 파일, 복구 창의 차이 보기도 `diffProjects` 를 그대로 쓴다.
- 이름은 화면에 보이는 단계 이름, 블록에 적어 둔 이름, Substation 의 Unit 이름이다. 블록 이름이 종류 말과 같으면 그 말을 쓴다(`신호 기다림`).
- 키보드로 고른 Unit · Device 의 좌표 상태 줄은 모델의 x, y 를 따라간다. 방향키 뒤의 실행 취소는 옮기기 전 좌표, 다시 실행은 옮긴 뒤 좌표다. 같은 선택을 끌어도 좌표가 바뀐다. 그 노드가 실행 취소로 없어지면 상태 줄은 비운다.

## 화면

Headless Chrome. 1280×800. 기기 픽셀 배율 1. 콘솔 오류 0. 문서 스크롤 0 (`scrollWidth` 1280, `scrollHeight` 800). 포인터 클릭과 키 입력은 Chrome 이 받았다.

5공정 예제 도면. Tab · Enter 로 CYL-01 을 고르고 Ctrl+D 로 복제한 뒤 방향키로 옮겼다. 상태 줄은 `S1 투입 › CYL-01 사본 (52, 110)`. 실행 취소 한 번은 `(42, 110)`, 한 번 더 하면 사본이 없어지고 상태 줄이 빈다. 이어서 S1 을 방향키로 `(40, 70)` 에 두고, 실행 취소는 `(30, 70)`, 다시 실행은 `(40, 70)` 이다. 같은 Unit 을 끌면 상태 줄이 `(160, 70)` 으로 바뀐다.

흐름 예제 2 를 저장한 뒤 S2 스토퍼 상승(정지)을 한 칸 내리고 신호 기다림을 더했다. 순서 줄은 `더함: 신호 기다림(읽기 결과 뒤) · 옮김: S2 스토퍼 상승(정지) 2번째 → 3번째`. 요약은 추가 1 · 삭제 0 · 바뀜 1. 내부 ID 는 줄에 없다.

## 하지 않은 것

- 차이 합치기, 줄 단위로 되돌리기, 글자 단위 차이
- 새 단축키
- `README.md`, `release/` 재빌드, 의존성 추가
- `styles.css` 에 새 규칙. 순서 줄은 있던 `project-diff.css` 를 그대로 쓴다
- 실행 규칙, 파일 형식

## 확인 필요

- 순서 줄만 보고 무엇이 바뀌었는지 알 수 있는가는 사람 검수(AC9)다. 이 문서는 완료로 적지 않는다.
- 목록 맨 앞에 더한 단계는 `(맨 앞)` 이다. 글이 6개를 넘으면 뺌 · 더함 · 옮김 순으로 앞 6개만 남긴다.
- 포인터로 다른 것을 고르면 키보드 상태 줄은 비운다(TURN-084). 이미 키보드로 고른 것을 끌면 좌표가 따라간다. 속성 칸에는 x, y 입력 칸이 없고, 선택을 바꾸지 않은 채 그 노드의 좌표가 바뀌면 같은 줄이 갱신된다.
