# TURN-095 보고서 · 인쇄용 보기 모양 맞추기

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.3.0`. 실행 규칙은 `seq-runtime/0.10.0`. `README.md` 와 `release/` 는 이 TURN에서 고치지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

실행 결과 보고서와 인쇄용 보기가 `src/ui/doc-frame.css` 와 `src/ui/docFrame.ts` 한 틀을 쓴다. 표지 요소 · 순서 · 클래스가 같다. 문서 종류만 「실행 결과 보고서」와 「설계 요약」으로 갈린다.

표지 순서. 제품 이름, 프로젝트 이름, 문서 종류, 한계 문구, 그다음 표(프로젝트 · 문서 · 시각 · rev · 실행 규칙 · 앱 버전 · 장비). 한계 문구는 둘 다 「검토 후보 — 논리 시뮬레이션, 실제 장비 제어 / 안전 검증 아님」이다. 시각은 `formatLocalClock` 이다. 저장된 값은 ISO 그대로 `title` 에 있다.

쪽 머리는 화면에서 숨고, 인쇄할 때만 쪽마다 프로젝트 이름과 한계 문구가 반복된다. 쪽 번호는 `n / N` 이다. Chrome 이 보고서를 A4 세로 5쪽(`1 / 5`), 인쇄용 보기를 A4 가로 17쪽(`1 / 17`)으로 나눴다. 2쪽에도 같은 머리가 있다.

표는 `doc-table` 이다. 숫자 · 시간 열은 `ecd-num`(오른쪽 · 고정폭 숫자 · 줄바꿈 없음 · 열 너비는 내용)이다. 긴 글 칸이 남는 폭을 쓴다. 머리 줄은 `table-header-group`, 줄은 `break-inside: avoid` 다. 긴 글은 줄바꿈이고 줄임표는 쓰지 않는다. 보고서 HTML 은 여전히 파일 하나다. 스타일은 안에 넣고, script · link · 글꼴 · 이미지 URL 은 없다.

상태 여섯(▶ 진행 중, ✓ 완료, ! 오류, ○ 대기, ? 미정, △ 가정)은 기호와 글자가 같이 나온다. 건너뜀은 ○, 정지는 △, 판정의 부족은 !, 사람 확인 후보는 △ 다. 자재 종류는 색 칸에 민무늬 · 빗금 · 점 · 가로줄을 글자로도 붙인다. 단계 표 · Gap · 구조 표의 열과 값은 그대로다.

## 화면

Headless Chrome. 뷰포트 1280×800. 기기 픽셀 배율 1. 콘솔 오류 0. 이 컴퓨터 시간대는 UTC 라 시각이 `(UTC)` 다.

포인터로 5공정 예제 사본을 열고, 자재 정의를 하나 더 넣은 뒤 ▶ 실행 · 끝까지로 돌렸다. 정의 추가로 rev 는 2 다. 보고서 메뉴의 「HTML 보고서」는 포커스 뒤 Enter 로 받았다. 인쇄용 보기는 「내보내기」를 눌러 열었고, 세로는 포커스 뒤 Enter, 가로는 다시 Enter, 닫기는 Esc 다. 인쇄용 보기를 열고 닫아도 모델은 그대로다. 시간 칸의 `text-align` 은 `right` 였다. 쪽 머리의 `display` 는 화면 `none`, 인쇄 `flex` 다.

## 확인 필요

- AC8 은 Matthew 검수 전이다. 이 문서는 완료로 적지 않는다.
- 표지에 「문서」와 「실행 규칙」이 양쪽 모두 있다. 보고서 표지에도 「장비」가 있다. 본문 표의 열과 값은 바꾸지 않았다.
- 보고서 표지의 시각은 내보낸 시각(로컬 + 시간대)이다. 가상 시각은 실행 요약의 「실행 시각」에 그대로 있다.
- Vitest 가 CSS `?raw` 를 빈 문자열로 바꿔, 테스트를 받는 두 파일만 `vite.config.ts` 의 `css.include` 에 넣었다. 앱 빌드의 `?raw` 는 원래 파일 내용이다.

- 로컬 참고: `npm test` 153파일 1183개, `tsc --noEmit` 통과. 통과 판정은 CI. CI 확인 대기 — 루카가 Actions로 확인.
