# TURN-019 다크 테마 에셋 카드 도식 선 색

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. `release/` 는 다시 빌드해 커밋하지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

다크 테마에서 에셋 라이브러리 카드 14종의 도식 선이 카드 바탕과 고른 카드 둘레 색 위에서 3:1 이상이 되게 했다. 라이트 테마와 「C 보관」은 파일에 있던 색 그대로다.

카드 도식은 `<img>` 로 그리면 페이지 CSS가 닿지 않는다. 도식 모드는 SVG를 카드 안에 그대로 넣는다. 선 `#245BCE` 와 채움 `#E5EDFF` 는 속성으로 남기고, 그 요소에 `slot-stroke` · `slot-fill` 을 붙인다. 다크 색은 `src/ui/slot-theme.css` 한 곳의 CSS 규칙이다. SVG 속성에 `var()` 를 넣지 않았다. `filter` 는 쓰지 않았다. 도면 캔버스 `Symbol` 과 트리 꺾쇠(`47069.svg` · `e5f85.svg`, 선 `#53647B`)는 그대로다.

| | 라이트 · C 보관 | 다크 |
|---|---|---|
| 선 | `#245BCE` (SVG 속성) | `#8FB4FF` |
| 채움 | `#E5EDFF` (SVG 속성) | `#243448` |

다크 채움은 카드 바탕 `#19283a` 보다 조금 밝은 어두운 파랑이다. 라이트 채움 `#E5EDFF` 이 흰 바탕 위에서 1.17:1 인 것과 같이, 이 채움은 카드 바탕 위에서 1.18:1 이다.

그림 칸은 100×48, 이름과의 간격은 16px 그대로다. 실사풍(AI)은 여전히 `<img>` 다. 그림이 없을 때의 「AI 이미지 미준비 → 도식」도 같은 칸이다.

## 측정

WCAG 대비. 선 `#8FB4FF` · 채움 `#243448`.

| 짝 | 대비 |
|---|---|
| 선 / `#19283a` (다크 카드 바탕) | 7.21:1 |
| 선 / `#203d4c` (다크 고른 색) | 5.53:1 |
| 선 / 채움 | 6.11:1 |
| 채움 / `#19283a` | 1.18:1 |

Chrome 157.0.8103.50, CSS 뷰포트 1280×800, devicePixelRatio 1. 콘솔 오류 0. 계산된 색이 위 값과 같았다. 라이트에서 선·채움은 `#245BCE` · `#E5EDFF`. 다크로 바꿔도 SVG 속성은 그 색이고, 계산된 색만 `#8FB4FF` · `#243448` 로 바뀐다. 카드 id·버전과 `rev 1` 은 그대로였다. 그림 칸 100×48, 이름까지 16px. 실사풍은 카드 14장 모두 `<img>` 이고 도식 클래스는 0개였다.

## 확인 필요

- AC10 사람 검수는 Matthew 몫이다. 이 문서는 완료로 적지 않는다. 다크에서 도식 선이 또렷한지는 스크린샷과 위 대비로 본다.
- `#53647B` 두 곳은 카드 도식이 아니라 트리 꺾쇠다. 카드 14종은 선 `#245BCE` · 채움 `#E5EDFF` 만 쓴다.
- 정식 파일 3종의 `fill="black"` 경로(선과 같은 자리를 닫은 겹침)는 TURN-006 과 같이 두었다. 보이는 선은 `#245BCE` 쪽이다.
- `scripts/capture-gui.mjs` 는 푸셔 칸을 `.slot-diagram img` 로 잰다. 도식 모드는 이제 SVG다. CI 는 이 스크립트를 돌리지 않아 파일을 고치지 않았다.
- `README.md` 상태 줄은 동시 진행 규칙에 따라 이 PR에서 고치지 않는다.
