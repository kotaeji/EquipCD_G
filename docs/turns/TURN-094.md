# TURN-094 저장 지점 (이름 붙인 버전)

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.3.0`. 묶음 형식은 `0.1.0`. `README.md` 와 `release/` 는 이 TURN에서 고치지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

5단계 「진단·저장·AML」의 「바뀐 것」 아래에 「저장 지점」을 두었다. 「저장 지점 만들기」는 이름(필수, 60자)과 메모(선택, 200자)를 받아 지금 모델을 이 브라우저에 남긴다. 시각과 rev 가 함께 남고, 모델 · rev · Undo 는 바꾸지 않는다. 명령 찾기의 「저장 지점 만들기」도 같은 창을 연다.

목록은 최신이 위다. 줄마다 이름, 이 컴퓨터의 시각(`2026-11-28 00:31 (UTC+9)`), rev, 메모가 있고, 「차이 보기」 · 「사본으로 열기」 · 「이 지점으로 되돌리기」 · 「이름 바꾸기」 · 「삭제」가 있다. 시각은 `src/ui/localClock.ts` 다. `title` 과 `<time dateTime>` 은 저장된 ISO(UTC)다.

차이 보기는 TURN-081 의 목록이다. 앞은 저장 지점, 뒤는 지금이다. 사본으로 열기는 새 ID 의 탭을 연다. 지금 탭은 그대로다. 되돌리기는 바뀌는 항목 수를 보여 준 뒤 모델을 그 상태로 둔다. rev 는 +1 이고, 실행 취소 한 번으로 돌아온다.

한 프로젝트에 20개까지다. 21번째를 만들 때는 가장 오래된 것을 지울지 묻는다. 저장소가 모자라면 만들기를 거절하고 모델은 그대로다. 프로젝트 JSON 에는 넣지 않는다. Workspace 묶음은 「저장 지점 포함」이 켜져 있을 때만 넣고, 기본은 꺼져 있다. 다시 가져오면 그 목록이 돌아온다. 프로젝트를 지우면 저장 지점도 지워지고, 삭제 영향 확인에 개수가 보인다.

## 하지 않은 것

- 자동으로 만드는 저장 지점, 저장 지점끼리 합치기, 서버 보관, 갈래
- `README.md`, `release/` 재빌드, 의존성 추가
- `styles.css` 에 새 규칙. 스타일은 `save-points.css`, 묶음 확인란은 `bundle-screen.css`
- `tests/turn054.test.ts` 수정
- 실행 규칙(`seq-runtime`)과 파일 형식 버전. 프로젝트 파일에는 필드를 더하지 않았다. 묶음 파일의 저장 지점은 선택 필드다

## 확인 필요

- 메모 상한 200자는 이 TURN에서 정했다. 요구에는 선택이라고만 있다.
- 저장 지점 본문은 프로젝트마다 키 하나(`ecd.v1.savepoints.<id>`)다. 묶음 가져오기는 프로젝트 쓰기와 한 트랜잭션이다. 프로젝트와 저장 지점 키를 합쳐 128키를 넘으면 가져오기를 거절하고 아무것도 바꾸지 않는다.
- 사본으로 연 프로젝트는 저장 지점 목록을 복사하지 않는다. 묶음에서 「사본으로 넣기」를 고르면 그 사본의 목록은 파일에 있던 지점으로 돌아온다.
- 며칠 치 작업을 안심하고 되돌릴 수 있겠는가(AC9)는 사람 검수다. 이 문서는 완료로 적지 않는다.
