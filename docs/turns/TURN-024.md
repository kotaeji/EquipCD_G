# TURN-024 흐름 실행 기록 — 갈래 정지 · 반복 안 분기 · 처음 N회 안내

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.3.0`. 실행 규칙은 `seq-runtime/0.3.1`. 그룹 규칙 `group-runtime/0.2.0` 은 코드에 남아 있다. `release/` 는 다시 빌드하지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

- 흐름 실행이 오류로 멈추면, 그 순간 진행 중이던 다른 단계 기록은 `stopped` 가 되고 `endMs` 는 멈춘 시각이다. 오류가 난 단계의 기록 · 코드 · 메시지는 그대로다. 실행이 끝난 뒤 `active` 기록은 없다.
- 실행 표와 결과 요약은 그 상태를 「정지」 글자로 보여 준다. 결과 요약 첫 줄에 「정지 N」이 붙고, 실행 · 건너뜀 · 정지 · 오류 · 대기 · 진행의 합은 단계 수와 같다.
- 한 번이라도 실행된 단계에는 건너뜀 기록을 남기지 않는다. 건너뛴 뒤 나중 회차에 실행되면 그 건너뜀 기록을 실행 기록으로 바꾼다. 끝까지 한 번도 실행되지 않은 단계는 건너뜀 기록이 하나다. `skippedCount` 는 그 단계 수다.
- 읽기 Action 의 「처음 N회만」 아래에, 그 결과 신호를 쓰는 분기 · 재시도가 없으면 「결과를 쓰는 분기 · 재시도가 없어 첫 실패에서 멈춥니다」를 보인다. 흐름이 없어도 같다. 있으면 보이지 않는다. 평탄한 실행은 여전히 첫 읽기 실패에서 `READ_FAILED` 로 멈춘다.
- `RUNTIME_RULES_VERSION` 은 `seq-runtime/0.3.1` 이다. `FILE_FORMAT_VERSION` 은 `0.3.0` 이다.

## 흐름 예제 건너뜀 수

전: 1 (NG 배출). 후: 1. 이유: 흐름 예제의 분기는 반복 밖에 있어서, 안 간 갈래는 처음부터 한 번도 실행되지 않는다. 총 시간은 `00:13.100`, 병렬 예제는 `00:02.500` 이다.

## 하지 않은 것

- 평탄한 실행의 읽기 실패 규칙. 첫 실패에서 멈추는 것은 그대로다.
- 파일 형식 버전
- 흐름 편집 화면. `src/ui/FlowEditor.tsx` · `src/ui/SfcView.tsx` · `src/model/flow.ts` · `src/model/commands.ts` · `tests/flow.test.ts` 는 TURN-023 과 겹치므로 그대로 두었다. `src/ui/Panels.tsx` 는 오류 주입 칸만 고쳤다. 시퀀스 표의 상태 칸은 이 턴에서 바꾸지 않았다.
- `src/runtime/group.ts`, `release/` 재빌드, 매뉴얼 · 기능 목록, 의존성 추가

## 확인 필요

- 갈래 충돌(`DEVICE_CONFLICT`)은 실행 전에 막힌다. 단계가 진행 중으로 바뀌기 전에 멈추므로 `stopped` 기록은 생기지 않고, `active` 기록도 없다.
- 시퀀스 편집 표(`Panels.tsx` 의 단계 상태)와 흐름 편집 · SFC 는 「정지」 글자를 아직 쓰지 않는다. 이 파일들은 이 턴에서 상태 표시를 고치지 않았다.
- 사용자 매뉴얼과 기능 목록의 규칙 표기 `seq-runtime/0.3.0` 은 이 턴에서 고치지 않았다. 상태 줄과 README 는 `seq-runtime/0.3.1` 이다.
