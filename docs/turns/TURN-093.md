# TURN-093 실행 준비 점검표

상태: 검토 후보. 사람 검수 전. 정식 릴리스가 아니다. 앱 버전은 `0.3.0-prototype` 그대로다. 파일 형식은 `0.3.0`. 실행 규칙은 `seq-runtime/0.10.0`. `README.md` 와 `release/` 는 이 TURN에서 고치지 않았다. CI 확인 대기 — 루카가 Actions로 확인.

## 한 일

6단계 「가동 조건」의 「준비 검사」를 줄 목록으로 바꿨다. 차단이 위, 경고가 아래다. 머리 요약은 있는 수만 적는다. 예는 `차단 2 · 경고 3`, 차단만 있으면 `차단 3`, 없으면 `실행 가능`.

- **차단.** `checkRunReadiness` 가 내는 것을 하나도 빼지 않는다. 줄은 종류 · 무엇 · 어디(Unit · Device · 단계 이름) · 「이동」이다.
- **경고.** 새 판정은 없다. 조건 검사의 미정 · 안내, 타임아웃이 동작 시간보다 짧은 Action, 가정인 동작 시간의 수, Interlock 후보 미확인 수, 그리고 이미 준비 검사에 있던 Interlock · 신호 기다림 안내를 모은다.
- 줄을 누르면 지금과 같은 세 줄(무엇 · 왜 · 어떻게)이 그 아래에 펼쳐진다. Enter 로 펼치고 Esc 로 접는다. 「이동」은 지금의 차단 이동과 같은 화면 · 같은 칸으로 간다.
- 모델을 고치면 표와 단계 바 6단계 배지 숫자가 바로 줄어든다. 배지 숫자는 표의 차단 수와 같다. 실행 중 · 되감는 중에는 표가 접힌다.
- 좁음(1024)에서는 가동 조건이 접힌 띠로 시작하고, 그 띠에 차단 수가 숫자로 보인다. 띠를 펼치면 점검표가 보인다.

새 스타일은 `src/ui/readiness-list.css` 에 두었다. 글자 · 간격은 `--fs-*` · `--sp-*` 만 쓴다. 타임아웃 비교 문장은 `src/ui/timeoutNote.ts` 로 옮겨 가동 조건 칸과 점검표가 같은 문장을 쓴다.

모델은 5공정 예제에서 타임아웃 두 개를 비우고, 다른 Action 하나의 타임아웃을 동작 시간보다 짧게 둔 것이다. 머리는 `차단 2 · 경고 3` 이고, 6단계 배지도 2 다.

## 하지 않은 것

- 새 검사 규칙, 자동으로 고치기, 실행 규칙, 파일 형식
- `README.md`, `release/` 재빌드, 의존성, `tests/turn054.test.ts`
- 조건 검사의 오류를 점검표에 넣기. 오류는 5단계에 그대로 있고, 실행 전 검사의 차단이 아니면 표의 차단이 아니다.

## 확인 필요

- 실행까지 무엇이 남았는지 한눈에 보이는가(AC9)는 사람 검수다. 이 문서는 완료로 적지 않는다.
- 조건 검사의 「경고 수준」은 미정과 안내로 읽었다. 오류도 표에 넣고 싶으면 범위를 다시 정해야 한다.
- 차단이 둘 이상이면 예전 문구 `남은 차단 N개` 가 요약 아래에 남는다. TURN-062 가 그 문구를 본다.
- 예제 3종은 실행 전 검사 결과가 지금과 같이 통과다. 가정 동작 시간과 미확인 Interlock 이 있어 화면은 `실행 가능` 대신 경고 요약이 나온다.
- 6단계 배지 숫자는 차단 수다. 배지를 열면 나오는 남은 항목(아직 실행하지 않음, 저장 안 됨)과는 개수가 다를 수 있다.
- 차단 코드는 줄 안에 남아 화면 읽기에서 들리고, 눈에는 보이지 않는다. 좁은 칸에서 영문 코드가 줄을 밀지 않게 하려는 것이다.
