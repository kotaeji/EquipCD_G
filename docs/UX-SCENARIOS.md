# Aurora Concept Designer — UX 시나리오

문서 버전: v0.3 / 2026-11-08 KST. 통합 요구의 동반 문서다. 여기의 흐름·화면 배치는 [설계 제안]이며 요구의 [확정] 목적을 구현 가능한 과업으로 구체화한다. UI 실행·사용성 테스트·상용 완성의 증거가 아니다. 비공개 외부 노트 주소/UUID는 포함하지 않는다.

## 1. 공통 원칙과 역할

[확정] 주요 사용자는 초기 장비 컨셉을 구성하는 설계자와 순서를 배우는 초보자다. 계층은 Equipment(Station)>Unit(Substation)>Device. Station은 장비 전체, Substation은 여러 Device와 복수 시퀀스 동시 Play/Pause/Resume 단위다. 모든 단계 왼쪽에서 Workspace/Project를 조작하고, 중앙은 과업별 카드/Canvas/편집/점검/실행으로 바꾼다.

[설계 제안] 기존 6단계 기준: ①입력·에셋 ②배치·연결 ③속성·Action ④자재·시퀀스 ⑤점검 ⑥실행·저장. 이전/다음과 자유 편집 왕복에서 같은 모델을 유지한다. 단계 수·세부 gate·자유 편집 정책은 최종 합의가 필요하다. A/B/C 테마는 유지한다. 생성 이미지와 와이어프레임은 실제 화면 캡처가 아니다.

각 과업은 사용자 목표, 진입 조건, 정상 흐름, 예외/복구, 보존 대상, 검수 연결을 가진다. ‘필수 누락/미정/가정/사람확인/미구현/선택 자료 미준비’를 하나의 체크 상태로 합치지 않는다. 저장 가능과 실행 가능, 위저드 완료와 Core 매핑/안전 검증은 다르다.

## 2. 시나리오

### UX-01 — 왼쪽에서 작업 시작·프로젝트 전환

- 목표/연결: C01·N03·WF-00. 초보자가 현재 작업 공간과 Project를 잃지 않는다.
- Given: 생성/열기 가능한 환경 또는 기존 Project가 있다. 저장 방식은 결정된 플랫폼 계약을 따른다.
- When 정상: 왼쪽 Workspace 생성/열기 → Project 선택 → 탭·현재 Project 표시 확인 → 중앙 1단계 또는 마지막 유효 뷰 진입.
- Then: 왼쪽·헤더·탭의 선택이 일치하고 다른 단계에서도 같은 작업공간 조작에 접근한다.
- 예외/보존: 최근 경로 누락은 재지정, 열기 실패는 기존 Project 유지. 미저장 Project 전환 취소는 선택/탭/중앙/모델을 모두 원상 유지한다. 실행중 Project 전환의 정확한 정지/조회 정책은 미정이다.
- 검수: N03-AC1/2, C01-AC1~3. 프로젝트 2개·미저장·누락 경로를 구분한다.

### UX-02 — 실제 AML을 읽고 중앙 카드에서 에셋 선택

- 목표/연결: F1·C02·C03·WF-01. 자료가 없으면 직접/라이브러리 경로로 시작한다.
- Given: 지원 subset에 맞는 AML 파일 또는 명시된 지원 한계를 가진 파일.
- When 정상: 읽기 요청 → CAEX 식별·XML/XSD/앱 의미 검사 상태 확인 → 중앙 카드 검색/분류 → 상세에서 속성·ports·Actions·지원 상태 확인 → 명시적으로 프로젝트 추가.
- Then: 실제 AML 원본에 연결된 정의와 인스턴스가 만들어지고 상세 열기만으로 모델이 추가되지 않는다. 구문 파싱만으로 완전 AML 지원을 표시하지 않는다.
- 예외/보존: 지원 밖 요소·누락 참조는 위치/적용 한계와 함께 진단하고 기존 설계를 유지한다. 자동 추출 저신뢰 후보는 사람 확인 전 반영하지 않는다. 빈 결과를 성공으로 표시하지 않는다.
- 검수: C02-AC4~7, C03-AC4/5, F1-AC1~5. 14종 샘플 구성은 제안이며 실제 준비 개수를 보고서로 대체하지 않는다.

### UX-03 — Substation/복합 유닛 배치·연결

- 목표/연결: N01·F2·C02·WF-02. 계층과 포트 의미를 이해한다.
- Given: Station과 사용할 Unit/Substation 템플릿이 있다.
- When 정상: 카드에서 복합 유닛 추가 → 중앙 Canvas → 자식 Device 확인 → 이동/정렬 → 물류/신호 연결 → 선택 상세 확인 → Undo/Redo.
- Then: Equipment/Unit ID는 유지하는 제안 계약에 따라 같은 객체로 식별되고 두 템플릿 인스턴스의 자식/Action/ports가 서로 분리된다.
- 예외/보존: 잘못된 포트·없는 참조·순환 소속을 알린다. 배경이 없어도 편집한다. 삭제 전 영향 참조를 표시하며 취소는 모델을 보존한다. 뷰 이동이 Device 소속 이동이 되지 않는다.
- 검수: N01-AC1~3, F2-AC1~5, C02-AC7.

### UX-04 — 능력·사양·Action과 가정 정의

- 목표/연결: F3·C08·WF-03. 장치가 제공하는 능력과 미정을 분명히 한다.
- Given: Device와 개념 Signal/Position을 가진 Substation.
- When 정상: 왼쪽 대상 선택 → 중앙 속성/Action 편집기 → pre/post·매개변수·완료 조건 → 자동 제공 능력표·근거 확인 → 정의 검사 → 가정/미정 또는 사람 확인 유지.
- Then: 값/단위와 가정/확인 상태가 구별되고 아직 실제 I/O 주소가 없어도 개념 설계를 이어간다.
- 예외/보존: 없는 완료 Signal, 타입/단위 불일치, 충돌 조건은 정상 완료로 숨기지 않는다. Interlock 후보 자동 확정 금지. 사용 중 Action 변경은 영향 시퀀스/점검/실행을 재평가한다.
- 검수: F3-AC1~5, C10-AC4. 고급 입력의 정확 조건 언어는 미정이다.

### UX-05 — 자재·경로·복수 시퀀스 작성

- 목표/연결: F4·F5·N02·WF-04. 물류 상태와 동작 순서를 함께 연결한다.
- Given: 자재 정의, Unit Action과 현재 Substation.
- When 정상: 크기/무게·초기 상태·경로 → Action/post에 상태전이 연결 → 시퀀스 목록에서 Draft 추가/선택 → DnD 또는 자연어 → 모호함 확인 → SFC 미리보기.
- Then: 같은 SequenceDraft 중간표현을 사용하며 어떤 Substation에 속한 시퀀스인지 알 수 있다. 직접 구조 지정은 불필요 AI를 호출하지 않는다.
- 예외/보존: 모호한 이름·미정 전이는 사람에게 노출한다. 한 시퀀스 내부 병렬 분기와 Substation의 여러 시퀀스를 혼동하지 않는다. 물류 연결만으로 자재를 자동 이동하지 않는다. 문장/가정/출처 보존.
- 검수: F4-AC1~5, F5-AC1~5, N02-AC1의 준비 데이터. 외부 추론 전송 동의는 별도다.

### UX-06 — 점검·Gap에서 근거로 왕복

- 목표/연결: F6·C10·WF-05. 미정/부족/확인 필요를 해결 가능한 위치로 연결한다.
- Given: Process 요구와 제공 능력의 비교 대상 리비전.
- When 정상: 5종 Gap 목록 → 근거/관련 단계 확인 → Canvas/Configurator/Lab 이동 → 수정 → 점검으로 돌아와 재분석.
- Then: 해결 일반 항목은 접고 이력은 남긴다. 오래된 분석과 최신 결과를 구별한다. 사람 확인이 필요한 간섭/안전 항목은 자동 확정하지 않는다.
- 예외/보존: 정보 부족은 ‘문제 없음’이 아니다. 삭제된 대상은 마지막 근거/ID를 보존한다. 논리 간섭과 정밀 물리 검증을 혼동하지 않는다.
- 검수: F6-AC1~5, C10-AC3/4. 위저드 방문 체크는 실제 gate 검사를 대신하지 않는다.

### UX-07 — Substation 동시 Play/Pause/Resume

- 목표/연결: N02·C04/C06·WF-06. 한 Substation의 복수 시퀀스를 조작한다.
- Given: 같은 Substation에 독립 시퀀스 2개, 초기값·실행 규칙·자원 정보가 있다.
- When 정상: 실행 대상/포함 시퀀스 확인 → 실행 전 검사 → Play → 시퀀스별 현재 단계/상태·가상 시각 관찰 → Pause → Resume → 결과/로그 확인.
- Then: 두 시퀀스가 하나의 실행 문맥에 있고 Pause/Resume는 정지·계속을 뜻한다. 공통 가상 시계·동결·Reset은 제안 실행 계약으로 명시한다.
- 예외/보존: 동일 Device 쓰기/공유 자재 충돌은 실행 전 차단·진단하는 제안. 임의 우선순위 진행 금지. 실행 중 다른 단계 조회는 상태를 초기화하지 않고 모델 편집은 차단한다. 한 시퀀스 오류의 그룹 전파는 미정이다.
- 검수: N02-AC1~5, X12/13. 실행 로그·가상 시각·최종 결과로 검증하며 애니메이션만으로 동시 실행 성공을 판단하지 않는다.

### UX-08 — AI 실사풍 토글과 문맥 보존

- 목표/연결: N04·C03·WF-01/02/07. 사진처럼 보이더라도 실제 촬영과 구별한다.
- Given: 같은 방향·모델 anchor에 맞춘 도식/AI 실사풍 쌍 또는 미준비 상태.
- When 정상: 카드 미리보기 → 상세 확인 → 배치 → 도식/AI 실사풍 전환 → 저장/재열기.
- Then: AI 생성·실제 촬영 아님 표기가 있고 방향·ports·계층·배치/연결·Action·자재/실행 상태가 보존된다.
- 예외/보존: 잘못된 방향/anchor·미준비·사용 조건 미확인은 도식 fallback과 검토 사유 표시. 새 실제 촬영 사진 수집으로 대체하거나 이미지의 가짜 부품을 모델에 자동 추가하지 않는다. 과거 사진 참조는 이력으로 보존한다.
- 검수: N04-AC1~5. 실제 생성 이미지/앱 토글은 후속 검수 대상이며 본 텍스트는 생성/품질 검증 실적이 아니다.

### UX-09 — 이전/다음·자유 편집·저장/재열기

- 목표/연결: C01/C05/C06/C10·N03·WF-00. 안내 흐름이 데이터를 잃지 않는다.
- Given: 연결·Draft·Material·가정과 미저장 변경이 있는 프로젝트.
- When 정상: 이전 → 라이브러리 → 자유 편집 → 위저드 복귀 → 저장 → 닫기/열기.
- Then: 같은 ID와 의미를 보존하고 UserView 현재 위치를 복원/안내한 뒤 실제 데이터 기준 gate 재계산.
- 예외/보존: 저장 실패는 미저장 변경 유지. 미지원 형식은 원본 자동 덮어쓰기 금지. 파손 UserView만 유효 단계로 복구하고 설계는 초기화하지 않는다. 실행 파일 열기를 자동 Resume하지 않는다.
- 검수: C01/C05/C06 AC, C10-AC2~5. 런타임 순간 상태 영구 저장은 미정이다.

### UX-10 — Lab 후보·Export를 준비 상태와 구별

- 목표/연결: F7/F8·C08·WF-05/07. 추천/매핑을 확정 실행과 구별한다.
- Given: 변형 범위/평가 기준 또는 확인된 외부 매핑 계약.
- When 정상: 후보/Pareto·탈락 이유·차이 또는 매핑 준비·가정/누락 미리보기 → 사람 선택/확인 → 명시 적용/내보내기.
- Then: 선택 전 원본 불변, Material/가정/출처/ID 보존. 실제 I/O 역매핑의 미일치는 사람 연결 후 반영한다.
- 예외/보존: AI/VC 실패·계약 불명·중복 주소는 성공으로 처리하지 않는다. 현재 위저드 6단계 완료가 F7/F8 구현·Core 전체 준비·실장비 안전 완료는 아니다.
- 검수: F7/F8 AC 전체. 외부 서비스 전송·실제 Core 버전·비용 상한은 기존 미정 유지.

### UX-11 — 요구 정본·History·UX/WF 관리

- 목표/연결: C11·N06/N07/N08. 사용자 입력은 읽기 전용으로 두고 정본을 일관되게 갱신한다.
- Given: 추가 요구와 기존 정본/History/UX/WF.
- When 정상: 입력 읽기 → 기존 ID 영향 분류 → 확정/제안/미정 → 정본·검수·시나리오/화면·변경이력 갱신 → 외부 반영 확인.
- Then: 정본 제목 고정·본문 버전·상단 History 연결을 유지하고 사용자 입력을 수정하지 않는다. History 생성/상단 링크 확인과 신규 v0.3 본문 저장 확인은 다른 사실이다.
- 예외/보존: 동일 개정 중복 삽입 금지, 저장 실패/충돌은 보존 후 보고. 공개본에 비공개 노트 URL/UUID 복사 금지. 실제 저장·구현·검증 결과는 근거와 연결해 별도 기록.
- 검수: N06-AC1~4, N07-AC1~4, N08-AC1~3. 초기에는 같은 봇의 통합 관리 권고, 독립 디자인/플랫폼 작업이 커지면 역할 분리 검토.

### UX-12 — 제품형 품질과 접근 가능한 작업 흐름

- 목표/연결: N05·QLT-01~08·WF-00~07.
- Given: A/B/C, 1280×800 및 1920×1080의 제안 검수 환경과 긴 한글/트리/표/로그.
- When 정상: 키보드로 왼쪽→단계→중앙→상세/팝업 이동, 목록별 스크롤, 테마 변경, 로딩/오류/미정/미저장/실행 상태 확인.
- Then: 핵심 조작이 가려지지 않고 포커스·선택·현재 문맥이 보인다. 대비 후보 기준을 실제 값으로 측정하고 간격/글자 역할/행동을 일관되게 유지한다.
- 예외/보존: 긴 이름은 줄바꿈/상세 경로, 작은 화면은 접근 가능한 패널 축소. 버튼/화면만 존재하는 미구현 기능은 정상 사용처럼 표시하지 않는다.
- 검수: N05-AC1~4. 화면 모형 확인과 실제 앱/사용성 검증 결과를 분리하며 상용 완성 인증으로 보고하지 않는다.

## 3. 시나리오 검증·변경 운영

[설계 제안] 각 기록은 UX ID, 요구/AC, WF ID, 입력 리비전, 전제·정상/예외, 보존 필드, 관찰 결과, 앱/규칙 버전, 실제 증거, 통과/실패/미검증을 갖춘다. 여기에는 실제 앱 결과를 기입하지 않았다. 요구 변경 시 연결된 시나리오·와이어프레임·AC를 같이 재검토한다. 다이어그램/이미지 생성 여부를 동작 검증 결과와 합치지 않는다.
